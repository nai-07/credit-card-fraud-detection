# Sentinel — Credit Card Fraud Detection System

A Python + machine-learning academic project demonstrating a transaction ingestion → preprocessing → model inference → risk triage workflow.

## Project structure

```text
credit_card_fraud_detection/
├── frontend/
│   └── app.py                 # Streamlit dashboard and user interface
├── backend/
│   ├── __init__.py
│   └── fraud_model.py         # Synthetic data, preprocessing, Random Forest, scoring
├── scripts/
│   ├── train_model.py         # Train and save the model
│   └── generate_data.py       # Generate a CSV demo dataset
├── models/
│   └── fraud_model.joblib     # Saved trained model and evaluation
├── tests/
│   └── test_model.py          # Automated tests
├── requirements.txt
├── .gitignore
└── README.md
```

**Architecture note:** This version does not have a separate database. Transaction history is held in Streamlit session state while the app is running; it is not persistent storage.

## Features

- Streamlit dashboard with transaction totals, risk bands, and recent high-risk records.
- Single-transaction risk checker.
- CSV batch analysis and downloadable scored results.
- Random Forest classifier with a preprocessing pipeline.
- Precision, recall, F1, ROC-AUC, PR-AUC, confusion matrix, and feature importance.
- Input validation and basic automated tests.

## Important data and safety note

The app uses **synthetic demonstration data** generated by `backend/fraud_model.py`. The labels are generated from artificial risk patterns. The metrics demonstrate the ML evaluation workflow only; they are not evidence of real-world bank fraud detection accuracy.

This is an educational demo. It has no bank/payment network integration and does not approve, decline, or block real transactions.

## Requirements

- Python 3.10–3.12 recommended
- VS Code

## Setup on Windows

Open this project folder in VS Code. In the terminal, run:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell blocks activation, open a Command Prompt terminal and run:

```bat
.venv\Scripts\activate.bat
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## Run the project

Train or refresh the saved model:

```powershell
python scripts/train_model.py
```

Start the dashboard from the project root:

```powershell
streamlit run frontend/app.py
```

Streamlit prints a local address, usually `http://localhost:8501`.

Generate a separate synthetic CSV file if needed:

```powershell
python scripts/generate_data.py
```

The generated CSV is placed in `data/`. That folder is ignored by Git because it contains generated data.

## Run automated tests

```powershell
python -m pytest -q
```

## Model design

- Random Forest classifier with class weighting.
- Numeric features passed through; merchant category one-hot encoded.
- Stratified holdout test split.
- Binary prediction threshold: 0.5.
- Dashboard risk bands: Low (<30%), Review (30–70%), High (>70%).

The binary classification threshold and dashboard risk bands serve different purposes. A transaction may be classified as legitimate at the 0.5 threshold while still appearing in the Review risk band.

## Batch CSV input columns

Required columns:

| Column | Meaning | Example |
|---|---|---|
| `amount` | Transaction amount | `2450.50` |
| `hour` | Hour of day, 0–23 | `22` |
| `merchant_category` | Merchant type | `Online Shopping` |
| `distance_km` | Distance from usual location | `120.0` |
| `transactions_last_hour` | Recent transaction count | `4` |
| `device_new` | New device: 0 or 1 | `1` |
| `international` | International transaction: 0 or 1 | `0` |

Optional column: `actual_fraud` (0 = legitimate, 1 = fraud), for comparing predictions with known labels.

## Limitations and future improvement

The current implementation uses synthetic data and a compact feature set. It does not include persistent transaction storage, real customer/card identity data, live geolocation, or payment-network actions. A future version could use a verified labelled dataset, add persistent database storage, and evaluate the model on data that reflects real transaction distributions.
